## 1. 문서 우선순위 트리 (Spec precedence)

제품 사양이 서로 충돌하면 위에 있는 것이 이긴다.

1. **해결된 Owner 결정** — `docs/decision_briefs/`의 `Resolved` 브리프, 그리고 작업 로그에 기록된 Owner 결정
2. **이 문서** — `docs/SOT.md`
3. **아키텍처 문서** — `docs/architecture/*.md`
4. **페이즈 문서** — `docs/phases/*.md`
5. **원천 기획** — `docs/plan/ideation.md` (참고 자료. 수정하지 않으며, 위 문서와 충돌하면 위 문서가 우선)

규칙:

- 하위 문서가 상위 문서와 충돌하면 하위 문서를 고친다. 하위 문서를 근거로 상위 문서를 조용히 바꾸지 않는다.
- **같은 층위 안**의 충돌(예: SoT 내부 모순, 아키텍처 문서끼리의 모순)은 임의로 고르지 않고 Owner에게 묻는다.
- **이 문서의 버전 갱신(내용 변경)은 작업자와 Owner의 논의와 합의를 거쳐서만 한다.** 작업자가 단독으로 요구사항을 바꾸지 않는다. **Owner가 작업자에게 위임한 판단의 결과도 합의다**(예: 문서 구조, 검증 지적을 보강하는 방식, 권장안 채택 위임). 합의 내용은 작업 로그의 "결정"에, 변경 요약은 §9 버전 로그에 남긴다.
- Owner 결정이 나오면 해당 브리프의 Resolution을 기록한 뒤 이 문서의 관련 절과 §9 버전 로그를 갱신한다.
- `CLAUDE.md`, `AGENTS.md`, `docs/guides/`는 **작업 방식**을 규정하며, 제품 사양 트리와는 별도의 축이다.

## 2. 제품 정의

- **한 줄 정의:** VS Code처럼 보이는 웹 IDE 안에서, 코드 주석을 읽고 지정된 변수 값을 바꿔 실행(`Ctrl+Enter`)하는 방식으로 진행하는 선택지형 스토리 어드벤처.
- **형태:** 브라우저 전용 정적 웹 애플리케이션. 백엔드·DB 없음.
- **첫 시나리오:** *Incident 02:14* — 플레이어는 비정상 시스템 장애를 조사하는 개발자.
- **시나리오 선택 (v0.8):** `main.py`에서 시나리오를 골라 진행한다. 현재 3개: *Incident 02:14*, *Thermal Drift*(데이터센터 냉각 이상), *Unlogged Run*(연구소 자동화 오류). §3.7.
- **개발 우선순위 (ideation §12):** 코드 편집의 직관성 → 파일 생성 경험 → 이야기의 몰입감 → 복잡한 코드 조작.

## 3. 핵심 게임 루프 (확정)

**파일 열기 → 주석 읽기 → 지정 변수 수정 → `Ctrl+Enter` 실행 → Terminal 결과 확인 → 다음 함수 또는 파일 해금**

- 실행 시 엔진은 현재 사건의 지정 변수 값만 추출·검증한다.
- 유효하지 않은 값이면 Terminal에 오류를 출력하고 **게임 상태를 바꾸지 않는다.**
- 스테이지 완료 조건을 만족하면 Explorer에 다음 파일이 추가되고, 플레이어가 그 파일을 열면 다음 스테이지가 시작된다.
- 한 번 생성된 파일은 유지되며 다시 열어볼 수 있다.

### 3.1 지정 변수 입력 유형 (MVP)

| 유형 | 예시 | 용도 |
| --- | --- | --- |
| 정수 | `action = 2` | 기본 선택지 |
| 불리언 | `override = True` | 특별 행동 |
| 수치 | `limit = 50` | 조건 변경 |
| 문자열 | `target = "A"` | 대상 선택 |

조건식 수정과 다중 변수 조합 선택은 P1(확장)이다.

### 3.2 편집 모델 ([DB-02](decision_briefs/02_editing_model.md) 확정)

- 플레이어는 지정 변수의 **값 부분만** 편집할 수 있다. 나머지 코드와 주석은 읽기 전용이다.
- 읽기 전용 영역에서의 입력은 무시된다. 게임 전용 경고 팝업은 띄우지 않는다(R-01).
- 키보드만으로 진행할 수 있게 한다(2026-10-23 Owner 합의, v0.9). 파일을 처음 보이거나 그 파일 내용이 바뀌면(새 사건 함수 추가, `main.py` 목록의 상태 표시 변경 등) 커서를 현재 사건의 첫 값 끝에 두고 그 줄이 보이게 스크롤한다. `main.py`에서는 `scenario` 값 끝이다.
- 모든 사건 함수(와 `main.py`)는 고칠 값 줄 바로 아래에 `# Ctrl+Enter(macOS는 Cmd+Enter)로 실행한다.` 한 줄을 둔다(v0.9, 시나리오 검증이 확인).

### 3.3 파일 안 사건 진행 ([DB-03](decision_briefs/03_scene_reveal_in_file.md) 확정)

- 스테이지 파일을 처음 열면 첫 사건 함수만 보인다.
- 사건을 해결할 때마다 파일 아래쪽에 다음 사건 함수가 추가된다. 실행 대상은 항상 가장 마지막 **사건** 함수다(아래 안내 함수는 사건이 아니다).
- 해결한 함수의 지정 값은 해결 당시 값으로 고정되며 다시 실행할 수 없다.
- 한 파일의 마지막 사건을 해결해 다음 사건이 다른 파일로 넘어가면, 방금 끝난 파일의 마지막 사건 함수 아래에 **다음 파일 안내 함수** `next_file()`이 추가된다. 안내 함수는 새로 생성된 파일 경로를 주석으로 알려주며, 고칠 값이 없다. 이 파일에서 `Ctrl+Enter`를 누르면 안내된 파일이 열린다(§3.5, v0.9). 문구는 엔진이 다음 파일 경로로 만든다(2026-10-23 Owner 합의, v0.7).

### 3.4 선택의 영향 범위 (MVP, [DB-01](decision_briefs/01_mvp_dynamic_content_scope.md) 확정)

- 이전 선택(플래그)에 따라 **새로 열리는 사건**의 주석과 Terminal 로그, 이후 전이와 엔딩이 달라진다.
- 이미 열린 파일의 소급 변경과 숨겨진 파일/함수는 P1이다. 단, §3.3의 다음 파일 안내 함수는 선택에 따라 달라지지 않는 진행 안내이므로 이 제외에 해당하지 않는다(v0.7).

### 3.5 실행 규칙 (2026-10-22 Owner 합의)

- `Ctrl+Enter`(macOS `Cmd+Enter`)는 **현재 사건이 들어 있는 파일이 활성 탭일 때만** 그 사건(§3.3의 마지막 함수)을 실행한다. 커서 위치는 상관없다.
- 다른 파일이 활성 탭이면 Terminal에 실행할 파일을 알려주는 한 줄만 출력하고 상태는 바꾸지 않는다. 따라서 새로 해금된 파일은 **열어야만** 진행할 수 있다(§3, AC-05).
- 예외(v0.9): 활성 탭이 `next_file()` 안내가 붙은 파일(진행이 떠난 파일)이면, `Ctrl+Enter`는 안내된 파일을 열고 활성 탭으로 만든다. 진행 상태는 바꾸지 않으며 Terminal에 한 줄을 남긴다. 파일을 여는 것이므로 AC-05와 충돌하지 않는다.
- 엔딩에 도달한 뒤에는 실행해도 Terminal 안내 한 줄만 출력하고 상태는 바뀌지 않는다.

### 3.6 저장과 복원

- 저장 대상: 진행 상태, 현재 사건에서 편집 중인 값, 열린 탭과 활성 파일.
- 새로고침 후 위 세 가지를 모두 복원한다(AC-08). 새로고침 직전의 편집까지 포함한다. 아직 해금되지 않은 파일의 탭은 복원하지 않는다.
- 시나리오가 갱신되어 저장 당시와 버전이 다르면, 유효한 진행 기록까지만 복원하고 편집 중이던 값은 기본값으로 돌아간다.
- 저장은 시나리오마다 따로 한다. 마지막으로 고른 시나리오도 저장해 새로고침하면 그 시나리오로 돌아온다(v0.8, §3.7).

### 3.7 시나리오 선택과 처음부터 다시 하기 (2026-10-23 Owner 합의, v0.8)

- `main.py`는 어느 시나리오에도 속하지 않는 공용 파일이다. 사용법과 시나리오 목록(번호, 제목, 한 줄 소개, 상태: 새 게임·진행 중·완료)을 주석으로 보여준다.
- 플레이어는 `main.py`의 `scenario` 값(번호)과 `restart` 값(`True`/`False`)을 바꾸고 `main.py`가 활성 탭일 때 `Ctrl+Enter`로 실행한다. 별도 메뉴 화면은 만들지 않는다(R-01).
- 고른 시나리오는 자기 저장에서 이어서 진행한다. 진행 중이면 현재 사건 파일이 열린다. `restart = True`면 그 시나리오의 저장만 지우고 처음부터 시작한다. 다른 시나리오의 저장은 건드리지 않는다.
- 시나리오를 바꾸기 직전에 지금 시나리오의 상태(편집 중인 값과 탭 포함)를 저장한다. 지금 열린 시나리오를 다시 골라도(기본값 그대로 실행 포함) 같은 순서로 저장 후 다시 열며, 진행은 그대로다.
- 바꾼 뒤 Terminal에는 그 시나리오의 기존 로그 다음에 선택 결과 한 줄이 붙는다.
- 처음 접속해 아직 고른 시나리오가 없으면 Explorer에는 `main.py`만 있다.
- `main.py`의 값은 저장하지 않는다. 열 때마다 지금 열린 시나리오 번호(없으면 1)와 `restart = False`로 시작한다.
- 잘못된 값(목록에 없는 번호 등)은 다른 사건과 같은 Traceback으로 알리고 아무것도 바꾸지 않는다.
- 추가 시나리오(*Thermal Drift*, *Unlogged Run*)는 짧은 구성이다: 파일 3개, 사건 7개, 엔딩 2개, 5~10분.

### 3.8 탐색형 사건의 다시 시도 (2026-10-23 Owner 합의, v0.10)

- 사건은 두 종류다. **탐색형**은 어디를 볼지 고르는 사건(시간대, 계정, 장치, 랙, 챔버, 프로젝트, 방, 기준값, 조회 기간)이고, **결정형**은 무엇을 할지 고르는 사건(조치, 보고, 보존·폐기 등)이다.
- 탐색형 사건만 다시 시도할 수 있다. 틀린 곳을 고르면 결과 로그와 "남은 기회 N번" 한 줄이 Terminal에 남고, 같은 사건이 현재 사건으로 남는다. 편집하던 값과 커서도 그대로다.
- 기회 수는 사건마다 정한다(선택지가 많은 시간대는 3번, 나머지는 2번). 마지막 기회까지 못 찾으면 "기회를 다 썼다"는 한 줄과 함께 "찾지 못함" 분기로 넘어간다. 단서를 읽을 이유와 못 찾은 경우의 이야기가 남도록 하기 위해서다.
- 기회 수는 그 사건의 주석에 "기회는 N번이다"로 적는다(시나리오 검증이 확인).
- 결정형 사건은 지금처럼 한 번 실행으로 확정된다.
- 틀린 시도도 진행 기록(`choices`)에 남아, 새로고침해도 남은 기회까지 복원된다.

## 4. 화면 구성 (확정)

VS Code를 연상시키는 다크 테마. MVP에서는 게임 진행에 필요한 최소 외형과 조작만 구현한다.

| 영역 | MVP 요구사항 |
| --- | --- |
| Explorer (좌) | 폴더/파일 트리, 해금된 파일만 표시, 클릭으로 파일 열기, 새 파일 추가 반영, 이전 파일 재열람 |
| Editor (중앙) | Python 문법 강조, 줄 번호, 탭, 지정 변수 편집, 함수 접기/펼치기, 수정 상태 표시 |
| Terminal (하단) | 실행 결과, 사건 결과 로그, 입력 오류, 새 파일 생성 로그 |
| Status Bar (최하단) | 언어(Python), 인코딩, 현재 파일/프로젝트 상태 |

## 5. MVP 범위

### 5.1 P0 — MVP 필수 (ideation §7.1)

- VS Code 스타일 메인 화면, Explorer, 파일 탭, Terminal, Status Bar
- Python 코드 편집기(Monaco)와 지정 변수 수정
- `Ctrl+Enter` 실행, 지정 변수 파싱·검증
- 함수 단위 진행, 장면별 스토리 분기
- 다음 스테이지 파일 동적 생성, 파일 클릭으로 스테이지 열기, 이전 파일 재열람
- 진행 상황 자동 저장, 새로고침 후 이어하기
- 샘플 시나리오 1개(스테이지 5개, 사건 함수 10~15개), 일반 엔딩 2개
- (v0.8) 짧은 시나리오 2개 추가와 `main.py` 시나리오 선택·처음부터 다시 하기(§3.7)

### 5.2 P1 — 확장 (MVP 제외)

조건식 수정 분기, 다중 변수 조합 선택, 복수 챕터·폴더 생성, 사용자 선택 이력, 스토리 되돌리기, 외부 시나리오 로딩(번들 밖에서 불러오기). 번들에 포함된 시나리오의 선택은 v0.8에서 MVP로 옮겼다(§3.7).
히든 엔딩도 P1이다 (ideation §4.3 "후속 버전으로 분리").
숨겨진 파일·함수, 진행에 따른 기존 파일 내용 변경도 P1이다 ([DB-01](decision_briefs/01_mvp_dynamic_content_scope.md)). 단, §3.3의 다음 파일 안내 함수는 예외다(v0.7).

### 5.3 P2 — 장기 (MVP 제외)

시나리오 제작 도구, 사용자 제작 스토리 공유, 다른 언어 테마, 복수 프로젝트, 실제 구문 기반 코드 퍼즐, 분기별 특수 이벤트.

### 5.4 MVP 스테이지 구성

| 스테이지 | 파일 | 주요 사건 |
| --- | --- | --- |
| 01 | `01_event_001.py` | 최초 장애 발생 |
| 02 | `02_security_audit.py` | 비정상 접속 기록 발견 |
| 03 | `03_power_control.py` | 전력 계통 이상 확인 |
| 04 | `04_sublevel_access.py` | 제한 구역 접근 |
| 05 | `05_case_report.py` | 사건 최종 처리 |

- 스테이지 파일 이름 앞에는 두 자리 순번을 붙인다. Explorer는 이름순으로 정렬하므로 순번이 곧 생성 순서가 된다(2026-10-23 Owner 합의, v0.7).
- 시나리오를 고른 직후 Explorer: `main.py`, 설정 파일 1개, `01_event_001.py`(v0.8부터 `main.py`는 공용 선택 파일, §3.7). 다른 시나리오도 같은 규칙으로 `cooling/01_…`, `lab/01_…`처럼 순번을 붙인다.
- 각 파일에 사건 함수 2~3개.
- 분기는 데이터 기반 상태 머신 + 공통 합류 지점으로 관리한다.

## 6. MVP 완료 기준 (v0.1)

아래 10개를 모두 만족하면 v0.1 완료로 본다.

| ID | 기준 |
| --- | --- |
| AC-01 | 게임 전용 화면 없이 IDE 인터페이스만으로 처음부터 끝까지 플레이할 수 있다. |
| AC-02 | 코드의 숫자나 변수를 수정해 선택할 수 있다. |
| AC-03 | 실행 결과에 따라 이야기와 상태가 변한다. |
| AC-04 | 스테이지 해금 시 Explorer에 새 파일이 나타난다. |
| AC-05 | 생성된 파일을 열면 다음 스테이지가 진행된다. |
| AC-06 | 이전 파일을 열어 내용을 다시 확인할 수 있다. |
| AC-07 | 잘못된 값을 입력해도 진행 상태가 손상되지 않는다. |
| AC-08 | 브라우저를 새로고침해도 진행 상태가 유지된다. |
| AC-09 | 선택에 따라 최소 2개의 결말에 도달할 수 있다. |
| AC-10 | 일반 플레이 기준 약 10~20분 분량이다. |
