### 3. 사건 파일 이름에 순번 (SoT v0.7 §5.4)

- 문제: Explorer가 이름순으로 정렬해 `case_report.py`가 맨 위, `power_control.py`가 가운데에 끼었다.
- 결정(Owner 합의): 정렬 규칙은 그대로 두고 파일 이름 앞에 두 자리 순번을 붙인다. `incidents/01_event_001.py` ~ `incidents/05_case_report.py`.
- 시나리오 `version` 3 → 4. 사건 id는 같아서 v3 저장의 진행은 이어진다. 편집 값은 버전 규칙(SoT §3.6)으로 초기화되고, 옛 경로 탭은 없는 파일의 탭을 버리는 `cleanWorkspace`로 닫힌다.
- `main.py` 안내 문구와 import 줄을 새 이름에 맞춤(숫자로 시작하는 모듈은 `import` 문으로 못 쓰므로 `importlib.import_module`).

### 4. 다음 파일 안내 함수 `next_file()` (SoT v0.7 §3.3, 아키텍처 §5.2)

- 문제: 새 파일이 생겨도 Terminal 한 줄뿐이라 보고 있던 화면에서는 변화가 없었다.
- 결정(Owner 합의, 문구는 작업자 위임): 현재 사건이 다른 파일로 넘어가면 떠난 파일의 마지막 사건 함수 아래에 안내 함수를 넣는다.
- 구현:
  - `derive`가 재생 중 "떠난 파일 → 넘어간 파일"을 기록하고, `renderStage(…, handoffTo)`가 `handoffBlock`으로 함수를 만든다. 문구·경로는 엔진이 만들며 시나리오 데이터에는 없다.
  - 넣는 위치는 파일 끝이 아니라 마지막으로 도달한 사건 함수 바로 아래(같은 들여쓰기). 처음엔 파일 끝에 붙였으나, 소형 시나리오처럼 `if __name__` 꼬리가 있는 파일에서는 그 블록 안으로 들어가 버려 위치를 바꿨다.
  - 이름 `next_file`은 엔진 예약어(`HANDOFF_FUNCTION`). 템플릿이 같은 이름을 쓰면 시나리오 검증이 실패한다.
  - 편집기: 열린 파일에 안내 함수가 새로 생기면 그 줄이 화면 밖일 때 스크롤만 한다.
