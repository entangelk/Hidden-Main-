# DB-03 — 한 파일 안에서 다음 사건 함수를 드러내는 방식

**상태:** Resolved
**관련 페이즈:** [P03](../phases/P03_story_engine_and_save.md)

## 결정이 필요한 것

ideation §2.3은 "하나의 파일 내부에서는 여러 함수가 순차적으로 열릴 수 있다"고만 하고, 아직 도달하지 않은 사건 함수가 화면에 어떻게 보이는지는 정하지 않았다. 각 스테이지 파일에는 사건 함수가 2~3개 들어간다(§4.2).

## 선택지

| 선택지 | 설명 | 장점 | 단점 |
| --- | --- | --- | --- |
| A | 파일을 열면 모든 사건 함수가 처음부터 보임. 현재 사건만 실행 대상 | 구현 가장 단순 | 뒤 사건의 주석(이야기·선택지)을 미리 읽을 수 있어 스포일러. 어느 함수가 현재 대상인지 따로 표시해야 함 |
| B | 사건을 해결할 때마다 파일 아래쪽에 다음 함수가 **추가**됨 | "코드 변경으로 결과를 표현"(R-06)과 일치. 스포일러 없음. 현재 대상이 항상 마지막 함수라 명확 | 파일 내용이 진행 상태에서 파생되어야 함(현재 설계와 일치). 추가 시 Editor 스크롤·포커스 처리 필요 |
| C | 모든 함수가 있으나 뒤 사건은 접힌 상태 + 본문이 가려짐(예: `# [locked]`) | 파일 구조가 처음부터 보여 분량 예측 가능 | 잠금 표시가 게임 UI처럼 보일 위험(R-01). 접기를 펼치면 보이지 않도록 별도 처리 필요 |

## 권장안 + 이유

**B.** 파일 단위 해금(새 파일 등장)과 같은 원리를 함수 단위에 적용하는 것이라 연출이 일관되고, 스포일러 문제가 없다. 파일 내용을 진행 상태에서 렌더링하는 [3계층 구조](../architecture/00_overview.md#5-파일-내용의-3계층)에서는 추가 비용이 거의 없다.

## 후속 고려 사항

- B 선택 시: 함수 추가 시 Terminal 로그 한 줄로 알릴지, 커서를 새 함수로 옮길지 P03에서 정한다.
- 이미 해결한 함수의 지정 값은 해결 당시 값으로 고정 표시하는 것을 기본으로 한다(재실행 불가). 다르게 하려면 별도 결정이 필요하다.

## 보류 / 범위 밖

- 숨겨진 함수(조건부로만 등장하는 함수)는 DB-01 범위
